**fill_unit** caveats:
- Every knob setting saturates at the same stride, so no separate fill unit is distinguishable from the read width.

**latch** caveats:
- The offset sweep does not separate these models: 32 B x 1 entry, 64 B x 1 entry, 128 B x 1 entry, 16 B x 2 entries, 8 B x 4 entries, 4 B x 8 entries. Every one of them predicts every offset measured. They are separable, and this sweep did not try the offsets that would do it: -56, +56, -72, +72 (the models disagree there and nowhere in the measured set). The simplest is reported, and it is a representative of the family, not a measurement.
- The densest offset sweep has no negative offsets, so an aligned block and a 'within +/-g bytes' proximity rule are the same prediction and this claim cannot tell them apart.
- Depth not determined: no `evict` series at spacing 32 B in a config where the latch resolved.
- 3 knob setting(s) show no data-side reuse at any offset, including offset 0 -- there a register DOES reach the latch, or disables the path that serves it: waitstates=0 icache=0 dcache=0 wrhighfreq=0, waitstates=1 icache=0 dcache=0 wrhighfreq=0, waitstates=2 icache=0 dcache=0 wrhighfreq=0
- 19 knob setting(s) re-read fast at every offset. That is consistent with both the latch and a cache holding both probe addresses, so those settings do not discriminate; the latch is inferred there, not measured.

**replacement_policy** caveats:
- A direct-mapped cache has no replacement policy: the victim is the line the index selects, and no policy can choose otherwise. This is a measurement, not a gap.

**waitstate_scaling** caveats:
- A wait-state setting of 0 contributes a legitimate zero to this fit and must not be read as an absent structure: at LATENCY = 0 a hit and a miss cost the same cycle, so the structure is still there and simply worth nothing (MEASURING_CHANNELS B3).
- At least one configuration shows a flat-zero differential at every wait state. That is the masking configuration (a cache holding both probe addresses), not evidence against the scaling.

**twin_calibration** caveats:
- The twin is NOT a zero here: at `waitstates = 0`, where a flash access cannot cost more than an SRAM one, `flash - twin` still reads +4.000 cycles per access in waitstates=0 icache=0 dcache=0 wrhighfreq=0. A NEGATIVE value means the flash buffer measures CHEAPER than its own SRAM twin, which is the bus-port signature: the probe loop runs from SRAM, so SRAM *data* loads contend with the loop's own instruction fetch while flash data loads sit on another port. Every figure derived by subtracting the twin in this configuration carries that bias, and correcting means subtracting it. The instrument-neutral quantity is `flash(LATENCY) - flash(0)` at the same stride, which cancels the loop entirely.
- The single-`reread` body reads +2.000 cycles in the same configuration, against +4.000 for the `walk` body. One number per (configuration, loop body) is the smallest honest unit: a longer loop body has idle cycles for an extra bus beat to hide in, so the two bodies are not interchangeable and are not averaged into one figure.

Cross-checks:
- Cross-check: the latch granularity equals the flash read width (32 B), as it does on every part in this repository.
- INSTRUMENT: in waitstates=0 icache=0 dcache=0 wrhighfreq=0 the SRAM twin is offset by +4.000 cycles per access at zero wait states, so every twin-subtracted figure measured in that configuration carries that bias -- correcting means subtracting it. The offset is NOT the same in every configuration and is not pooled; see the twin_calibration claim for the per-configuration table.
